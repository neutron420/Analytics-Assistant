## 1. Quality Analytics Philosophy & Principles
Machine translation evaluation traditionally suffers from two extremes:
1. **Opaque Neural Metrics (BLEU/COMET)**: Require paired ground-truth references which do not exist in live production inference, or require heavy secondary neural networks that introduce prohibitive latency and cost.
2. **Zero Telemetry**: Relying purely on raw user complaints.

Our platform adopts a **transparent, auditable heuristic quality model** designed for real-time operational telemetry and big data batch verification. 

> **Important Analytical Disclaimers**:  
> 1. The `quality_score` and `quality_category` generated by this platform are operational quality heuristics. They measure structural health, user satisfaction, and generation stability, rather than representing an infallible claim of absolute semantic correctness.
> 2. Model confidence scores must be interpreted carefully: high token certainty does not guarantee semantic or cultural appropriateness.
> 3. The platform does not claim to possess an infallible automated translation quality detector. Quality insights are designed to assist human-in-the-loop audit and prompt tuning.

## 2. Core Quality Dimensions & Signals

| Dimension | Signal / Metric | Definition | Optimal Range | Risk Indicator |
| :--- | :--- | :--- | :--- | :--- |
| **Linguistic Structure** | Character Length Ratio ($R_L$) | $R_L = \frac{\text{Length}(\text{Translated Text})}{\text{Length}(\text{Source Text})}$ | Varies by language pair (0.7 – 1.8) | $R_L < 0.3$ (Truncation) or $R_L > 3.0$ (Repetition) |
| **Model Certainty** | Confidence Score ($C$) | Output token logprob confidence or normalized provider confidence (0.0 to 1.0) | $0.80 \le C \le 1.00$ | $C < 0.60$ (Uncertain / Ambiguous) |
| **User Reception** | Feedback Score ($S_f$) | Direct human evaluation (`GOOD` vs. `POOR`) | 100 (`GOOD`) / 85 (Unrated) | 20 (`POOR`) |
| **Operational Health**| Latency Score ($S_t$) | Round-trip inference latency penalty | $< 2500\text{ ms}$ | $> 5000\text{ ms}$ (Degraded user experience) |
| **Contextual Slices** | Language Pair & Option | Segmented by pair (`en-hi`, `en-es`, etc.) and style (`LITERAL`, `NATURAL`, `FORMAL`) | N/A | Language-specific degradation |
| **Provider Slice** | Translation Provider | Categorized by active provider (`huggingface`, `cohere`, `mock`) | N/A | Provider-specific latency spikes |

## 3. The Composite Quality Score Formula

The Composite Quality Score ($Q$) is calculated on a 0 to 100 scale:

$$Q = \left( w_c \cdot C_{\text{scaled}} \right) + \left( w_l \cdot S_{\text{length}} \right) + \left( w_f \cdot S_{\text{feedback}} \right) - P_{\text{latency}}$$

### 3.1 Weight Assignments
- **Confidence Weight ($w_c$)**: $0.35$ (35%)
- **Length Consistency Weight ($w_l$)**: $0.35$ (35%)
- **Human Feedback Weight ($w_f$)**: $0.30$ (30%)
- **Latency Penalty ($P_{\text{latency}}$)**: 0 to 10 point deduction for excessive lag

### 3.2 Component Calculations

#### A. Scaled Confidence ($C_{\text{scaled}}$)
$$C_{\text{scaled}} = \begin{cases} C \times 100 & \text{if confidence is available} \\ 85.0 & \text{if confidence is unmeasured (neutral baseline)} \end{cases}$$

#### B. Length Consistency Score ($S_{\text{length}}$)
Because linguistic expansion varies by target script, we define pair-specific expected ratios $[\mu_{min}, \mu_{max}]$:
- Latin $\to$ Latin (`en-es`, `en-fr`): $[0.85, 1.35]$
- Latin $\to$ Germanic (`en-de`): $[0.90, 1.45]$ (compound words increase length)
- Latin $\to$ Indic (`en-hi`, `en-bn`): $[0.75, 1.40]$
- Latin $\to$ Japonic (`en-ja`): $[0.40, 0.95]$ (compact Kanji representation)

$$S_{\text{length}} = \begin{cases} 
100 & \text{if } R_L \in [\mu_{min}, \mu_{max}] \\
\max\left(0, 100 - 150 \cdot |\mu_{min} - R_L|\right) & \text{if } R_L < \mu_{min} \\
\max\left(0, 100 - 100 \cdot |R_L - \mu_{max}|\right) & \text{if } R_L > \mu_{max} 
\end{cases}$$

#### C. Feedback Factor ($S_{\text{feedback}}$)
$$S_{\text{feedback}} = \begin{cases} 
100.0 & \text{if user rated 'GOOD'} \\
20.0 & \text{if user rated 'POOR'} \\
85.0 & \text{if unrated (assumed baseline satisfactory)}
\end{cases}$$

#### D. Latency Penalty ($P_{\text{latency}}$)
$$P_{\text{latency}} = \begin{cases}
0 & \text{if } t \le 3000\text{ ms} \\
\min\left(10, \frac{t - 3000}{500}\right) & \text{if } t > 3000\text{ ms}
\end{cases}$$

## 4. Quality Categorization Tiering

| Category | Score Threshold ($Q$) | Operational Interpretation |
| :--- | :--- | :--- |
| **`EXCELLENT`** | $85.0 \le Q \le 100.0$ | High confidence, standard length ratios, positive or unflagged reception. |
| **`GOOD`** | $70.0 \le Q < 85.0$ | Stable translation with minor length deviations or neutral baseline scores. |
| **`NEEDS_REVIEW`** | $50.0 \le Q < 70.0$ | Marked length anomalies, elevated latency, or marginal confidence scores. |
| **`POOR`** | $Q < 50.0$ | Confirmed negative human feedback (`POOR`) or critical structural failures. |

## 5. Anomaly Detection Engine

The anomaly detection engine runs during the PySpark batch pass to flag high-risk translations into the `analytics_anomalies` table:

```
                            [ Candidate Translation ]
                                        |
         +------------------------------+-------------------------------+
         |                              |                               |
         v                              v                               v
[ Length Ratio Check ]         [ Latency Spike Check ]       [ Negative Feedback Check ]
Ratio < 0.25 OR Ratio > 3.5    Latency > 8,000 ms             Rating == 'POOR'
         |                              |                               |
         +------------------------------+-------------------------------+
                                        | (Any trigger matches)
                                        v
                         [ Flag Anomaly in PostgreSQL ]
                         [ Surface on Grafana Triage ]
```
