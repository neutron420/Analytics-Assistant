## 1. OPUS-100 Overview & Rationale
**OPUS-100** is an open-source, multilingual parallel translation corpus covering 100 languages, extracted from the OPUS project. It provides realistic, sentence-aligned translation pairs harvested from open web subtitles, software localization files, documentation, and legislative records.

### Why OPUS-100 Is Used:
1. **Academic & Industry Standard**: Widely cited benchmark for multilingual machine translation quality.
2. **Linguistic Diversity**: Contains both high-resource (French, Spanish, German) and medium/lower-resource or morphologically complex languages (Hindi, Bengali, Japanese).
3. **Realistic Data Artifacts**: Contains natural real-world variations, sentence fragments, idiomatic phrases, and technical terminology.

## 2. Strict Data Boundary Separation

> **CRITICAL ARCHITECTURAL DISTINCTION:**
> OPUS-100 is purely a parallel text corpus. It does NOT contain operational telemetry, latency, provider tags, confidence scores, or user ratings. 
> The platform enforces three distinct data tiers:

```
+-----------------------------------------------------------------------------------+
| TIER 1: BASE CORPUS DATA (Directly from OPUS-100)                                 |
| - source_text (string)                                                            |
| - translated_text (string)                                                        |
| - source_language (string ISO-639-1)                                              |
| - target_language (string ISO-639-1)                                              |
+-----------------------------------------------------------------------------------+
                                         |
                                         v (Enriched during staging / live runtime)
+-----------------------------------------------------------------------------------+
| TIER 2: APPLICATION & SERVICE METADATA (Generated by System / Users)              |
| - request_id / record_id (UUID)                                                   |
| - provider (string: huggingface, cohere, mock, opus100_baseline)                  |
| - translation_time_ms (integer)                                                   |
| - confidence_score (float 0.0 - 1.0)                                              |
| - translation_option_style (enum: LITERAL, NATURAL, FORMAL)                       |
| - user_selected (boolean)                                                         |
| - feedback_rating (enum: GOOD, POOR, NULL)                                        |
| - feedback_reason (enum: INCORRECT_MEANING, GRAMMAR, TOO_LITERAL, etc.)            |
| - created_at (timestamp)                                                          |
+-----------------------------------------------------------------------------------+
                                         |
                                         v (Derived inside PySpark batch jobs)
+-----------------------------------------------------------------------------------+
| TIER 3: DERIVED ANALYTICS FEATURES (Calculated by PySpark)                        |
| - source_char_length (integer)                                                    |
| - translation_char_length (integer)                                               |
| - source_word_count (integer)                                                     |
| - translation_word_count (integer)                                                |
| - length_ratio (float: translation_length / source_length)                        |
| - quality_score (float 0.0 - 100.0)                                               |
| - quality_category (enum: EXCELLENT, GOOD, NEEDS_REVIEW, POOR)                     |
| - performance_category (enum: FAST, NORMAL, SLOW, TIMEOUT)                       |
| - anomaly_flag (boolean)                                                          |
+-----------------------------------------------------------------------------------+
```

## 4. Ingestion & Enrichment Pipeline

### 4.1 Ingestion Verification
- Ingested via `scripts/download_opus100.py`.
- Formatted as newline-delimited JSON (`train.jsonl`).
- Raw dataset manifest stored at `data/raw/opus100/manifest.json`.

### 4.2 Synthetic Telemetry Enrichment Strategy (Phase 9)
To populate baseline operational volume for PySpark and Grafana before months of live interactions accumulate:
- An enrichment script (`scripts/enrich_baseline.py`) iterates over the raw corpus pairs.
- Injects:
  - `provider = 'opus100_baseline'`
  - Realistic latency distributions (log-normal, 800ms–1,800ms)
  - Simulated confidence scores (beta distribution, ~0.82–0.95)
  - Style variants (`LITERAL`, `NATURAL`, `FORMAL`)
  - Realistic user feedback distribution (85% Good, 15% Poor with defect reasons)
  - Distributed historical timestamps across the past 30 days.
- Output is written as Snappy-compressed Parquet files in `data/interim/enriched_baseline/`.

## 5. Data Validation & Hygiene Rules

| Rule ID | Name | Constraint / Action |
| :--- | :--- | :--- |
| **DV-01** | Non-Null Constraint | Rows with null `source_text` or `translated_text` are discarded. |
| **DV-02** | Non-Empty Constraint | Strings with length 0 after `strip()` whitespace are discarded. |
| **DV-03** | Length Boundaries | $1 \le \text{source\_char\_length} \le 5,000$. Strings exceeding 5,000 characters are rejected. |
| **DV-04** | Deduplication | Rows with identical source text are deduplicated. |
| **DV-05** | Unicode Normalization | Text is normalized to Unicode NFC (Canonical Composition). |
| **DV-06** | Identical Pair Filtering | If `source_text == translated_text` and source language $\ne$ target language, flag as untranslated artifact. |
